# Testing

1. Translate each Issue criterion into positive and relevant negative tests.
2. Run the least-cost sufficient unit, integration, E2E, accessibility, and manual checks from `TEST_PLAN.md`.
3. Record exact command/environment/result or why it could not run.
4. File reproducible bugs as Issues; do not hide failures in a chat response.
5. In the PR, report criterion-by-criterion status, evidence, severity of open defects, and release recommendation.
