# Project Reporting

1. Inspect GitHub Project fields, open/closed Issues, PR review/merge state, and Action results. Do not use chat claims as data.
2. Reconcile and timestamp `STATUS.md`: counts, milestone health, completed/in-review/next, blockers, decisions, risks.
3. Explain health based on evidence, critical path, and changed risks—not percent-complete theatre.
4. Link every material claim. Clearly mark missing data and uncertainty.
5. Send the human a short update: outcome, changes since last report, next decision, and deadlines/impact.
