# Product Specification

## Steps

1. Read accepted requirements; challenge any solution framed as a user need.
2. Define primary users, job-to-be-done, current pain, release outcome, non-goals, and measurable success in `PROJECT.md`.
3. Write main and failure/empty-state journeys in `REQUIREMENTS.md`.
4. Slice MVP so each slice delivers a coherent outcome; defer nice-to-have work explicitly.
5. Send material product trade-offs or open decisions to the human gate.

## Do not

Add features, analytics, integrations, accounts, or data collection without an accepted requirement.
