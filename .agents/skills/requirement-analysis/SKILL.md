# Requirement Analysis

## Input

User request, existing product evidence, constraints, and stakeholder answers.

## Steps

1. Separate verified facts, assumptions, preferences, and unknowns.
2. Identify user, job, desired outcome, constraints, non-goals, risk, and success measure.
3. Write stable FR/NFR IDs in `REQUIREMENTS.md`; express acceptance as observable given/when/then behaviour.
4. Put questions that materially change scope in the Open Questions table; do not invent answers.
5. Ask the accountable human to accept requirements before implementation Issues move to Ready.

## Output checklist

- Every requirement is necessary, unambiguous, testable, traceable, and prioritized.
- Non-functional needs cover appropriate performance, security, accessibility, reliability, privacy, and compliance concerns.
- Assumptions and exclusions are visible in `PROJECT.md`.
